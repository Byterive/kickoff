# project-bootstrap (the /kickoff flow)

Input: PROFILE (ask if missing; "custom" builds one, see `kit/profiles/custom.md`). KIT = `<skill base dir>/../../kit`. Follow `KIT/MASTER_SETUP_PROMPT.md`. Flags the user may pass: `--dry-run` (list every file and plugin change, write nothing); `--plan-only` (do steps 0-2 only: draft PROJECT_BRIEF.md, then write DECISIONS.md with an "Unresolved decisions" section listing every open choice that changes scope; create no folders, tools, hooks or settings; STOP until the user approves, then they re-run /kickoff without the flag).

Order: (0) `git status --short`; uncommitted changes -> ask to commit or confirm backup. Detect state: PROJECT_STATUS.md exists -> tell the user to run /resume instead; files but no `_audit/` -> run project-audit first; empty -> continue. (0b) Undo record: before creating anything run `python KIT/tools/undo.py <root> --snapshot`; after step 5 run `python KIT/tools/undo.py <root> --record` so /kickoff:undo can remove what bootstrap created. (1) Brief: read PROJECT_BRIEF.md, else ask <=5 questions (goal, profile, sources, never-do, next steps) with AskUserQuestion and draft it for review. (2) Profile: built-in, `~/.claude/kickoff/profiles/<name>/`, or custom interview. (3) Plugins: brief section 10 if filled, else ask once: Minimal / Recommended (profile preset, default) / Keep all / Select; apply with `python KIT/tools/proj_toggle.py preset <profile> --tier <t>` (or `off <names>`), preview with `--dry-run`, record the choice in DECISIONS.md. (4) Build, showing each file first: skeleton, tools/ (incl. proj_toggle.py, doctor.py), PROJECT_STATUS.md, CLAUDE.md (max 200 lines, "How to verify" only from commands FOUND in the repo, marked FOUND/GUESSED/NOT FOUND), DECISIONS.md and NEXT.md from KIT/templates, `.gitignore` (KIT/gitignore/common + profile) and `.gitattributes` (never overwrite; append missing lines), merge KIT/templates/settings.starter.json into .claude/settings.json (never read .env), pre-commit hook if git. (4b) Guide: if brief section 11 is empty ask once "Build a plain-language guide? No / Local"; on Local write `.kickoff/guide.json` from `KIT/templates/guide.json.template` (leave `hub` empty: the guide reads `~/.claude/kickoff/config.json` itself, so no local path lands in the project), and if the `guidebook` command exists run `guidebook init --dry-run` and show the proposed versions (contract: `KIT/GUIDE_CONTRACT.md`). (4a) Once the files exist run `python KIT/tools/upgrade.py <root> --profile <PROFILE> --sections yes --clarity yes --apply`: it adds the clarity rule block to CLAUDE.md, REQUIREMENTS.md and the status sections (How to run, Setup, Data, Troubleshooting, pre-filled as GUESSED); show them as a numbered brief with your recommendation and the question for each, and note my decision against each number; it also copies `.kickoff/kit/` (CLAUDE_INSTRUCTIONS.md, WRAPUP_PROMPT.md, which CLAUDE.md points to), `.kickoff/presets/` and the tools, never overwriting. (4c) Tracking fields: if brief section 12 is empty ask once "Add tracking fields? None / Fields only / Plan (fields + phases, dates, priority)"; unless None, run `python KIT/tools/upgrade.py <root> --fields fields|plan --apply` (contract: `KIT/FIELDS_CONTRACT.md`; optional), and fill `target_date`/`deadline` only from the brief. With Plan: interview me for phases (offer the profile's "Default phases"), rough dates and priority (blank = not set), run `python tools/plan.py init --profile <PROFILE>` (or `--phase NAME` for each phase), write my answers into `.kickoff/plan.json` (this is the one time you may set planned dates and priority, because I gave them), then `plan.py validate` and `plan.py render-status --write PROJECT_STATUS.md`. See `KIT/PLAN_SCHEMA.md`. (4d) VS Code: `python KIT/tools/vscode_ext.py <root> --profile <PROFILE>` (dry run), show the extensions and settings, write `.vscode/extensions.json` with `--apply` only after I say yes (merge, no overwrite, never installs). (4f) Claude contribution line: ask once "Add the Claude contribution line to commits and PRs? No (default) / Yes" (Yes = the Co-Authored-By trailer on commits and the Generated-with line on PR descriptions); run `python KIT/tools/attribution.py <root> --set yes|no --dry-run`, show it, then without `--dry-run` after my answer (writes `.kickoff/attribution.json` and the CLAUDE.md Git rule; no git hook), record the answer in DECISIONS.md. (4e) Companion plugins: `python KIT/tools/companions.py <root> --profile <PROFILE>`; for each missing plugin ask me, and run its `claude plugin install` line only after my yes for that plugin; then start a new session. (5) Run build_index, check_budgets, `python tools/doctor.py`; show root INDEX.md, PROJECT_STATUS.md and the doctor result; tell the user to start a new session to apply plugin changes; STOP until they say go.
Never move or delete files without an approved old-path -> new-path plan. Never add Claude co-author attribution unless I chose Yes in step 4f (see `.kickoff/attribution.json`).
