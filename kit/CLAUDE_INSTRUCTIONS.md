# Claude operating instructions

## Reading (progressive disclosure)
- Start every session with root `INDEX.md` and `PROJECT_STATUS.md`. Follow indexes and frontmatter
  downward; open a file body only when its summary says it is relevant. Never read whole folders.
- Raw data and binaries are never read directly; read the doc that describes them.

## Writing
- Every .md (except INDEX.md, README.md, CLAUDE.md) has frontmatter: title, summary (one specific
  sentence), keywords, status, updated, plus profile fields.
- Keep files short. If one grows past budget, split it into focused files, do not stuff it.
- INDEX.md files are generated by `python tools/build_index.py`; never hand-edit.

## Facts and honesty
- Not in the files -> write UNKNOWN. Never invent settings, results, versions or sources.
- Conflicting sources -> list both, mark CONFLICT.
- Never overwrite a conclusion silently: mark the old one `superseded` and link the new one.
- Report failures and skipped steps plainly.

## After each meaningful step
Update the matching file (knowledge, script header, result report, finding, data-source doc) and
PROJECT_STATUS.md; refresh `updated:`. Do not batch everything to the end.

## Before ending a session
Run `python tools/build_index.py` then `python tools/check_budgets.py`; fix failures by condensing
or splitting. Ask before raising a budget. List every file created or changed.

## Verification (definition of done)
- Done = the commands in CLAUDE.md "How to verify" pass and you quote their real output.
  UI work also needs a screenshot you looked at. Never write "should work".
- Commands come from the repo (README, scripts, CI config). Not found -> UNKNOWN, never guessed.
- When corrected, add one line to CLAUDE.md "Mistakes Claude made before". Keep CLAUDE.md under 200 lines.
- Use the `verifier` agent for an independent check when the work is non-trivial.

## Clarify before you record or build
When a new phase starts, a new requirement is added, or anything new needs a decision: stop and ask first with a numbered brief (options, your
recommendation, the question), wait for an explicit answer to each number, and record what it changes (DECISIONS.md, the plan, REQUIREMENTS.md)
before building. Never treat one "yes" as covering a point it was not asked about; list anything dropped and get an explicit OK. The full rule
is the marked block in CLAUDE.md (added by /kickoff:upgrade).

## Safety
- Ask before moving, renaming or deleting files, and before any irreversible or outward-facing action.
- Never commit secrets, keys, certificates or credentials. Record only where they are stored.
- Follow the profile's "Never do" list.

## Git
- Commit only when asked. NEVER add `Co-Authored-By: Claude` or any "Generated with Claude" line
  to commits or PR descriptions.
